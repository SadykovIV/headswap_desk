# DriveDeck 0.6.9 для HeadSwap Desktop (code334)

Текущая адаптация основана на [официальном DriveDeck 0.6.9 code331](https://github.com/RotkivKiv/DriveDeck-Updates/releases/tag/stable-code331). Обновление сохраняет отдельный пакет `ru.drivedeck.headswap`, настройки двух окон, управление DPI из HeadSwap и кнопки полноэкранных приложений. Выбор системного лаунчера, штатный обновлятор DriveDeck и изменение экрана телефона по-прежнему отключены. Нельзя заменять адаптацию обычным APK автора.

В `profiles.py` закреплены SHA-256 двух поддерживаемых исходных APK. Для 0.6.9 выбираются `patch_069.py` и `app_update_patch_069.py`, для прежнего 0.6.8 сохраняется старый адаптер. Имена обфусцированных методов проверяются до компиляции и передаются helper-коду через сгенерированный `CompanionSymbols`; неизвестный APK не патчится. Для текущего выпуска укажите `DriveDeck-0.6.9-code331.apk` в [команде пересборки](#пересборка). Результат — `DriveDeck-HeadSwap-0.6.9-code334.apk`.

| Вход 0.6.9 | SHA-256 |
| --- | --- |
| DriveDeck-0.6.9-code331.apk | `e32ac90ed66d7d325653ed475cd3623d41d7737aeb321813991aedab7b06a003` |

После сборки `package.py` автоматически выбирает соответствующую версию и формирует `DriveDeck-0.6.9-code331-to-HeadSwap-code334-patch.zip` и `DriveDeck-0.6.9-source-patches.zip`. Восстановление из бинарного патча должно совпасть с SHA-256 собранного APK. Успешная сборка не заменяет проверку на Android: `patch-report.json` содержит результаты сборки, а проверки приложения записаны отдельно в [отчёте HeadSwap 0.6.3](../../docs/TESTING-0.6.3.md).

В HeadSwap Desktop 0.6.3 **шторка уведомлений на ГУ временно отключена** общим флагом `HuNotificationFeature.AVAILABLE = false`. Code334 содержит совместимый вход через индикаторы связи в левой панели, но HeadSwap не выдаёт capability уведомлений и отклоняет открытие шторки и карточек. Поэтому этот вход в текущем выпуске не открывает уведомления. Это не отключает ввод кода сопряжения в уведомлении телефона, подсказки навигации или сведения о музыке на приборной панели.

APK выпуска code334: SHA-256 `7cde71424f2d70b505033ee2e246101bc31c66f8de67493e533d5593817aa356`. Проверки ранних сборок с включённой шторкой сохранены как история в [отчёте интеграции](../../docs/NOTIFICATION-SHADE-INTEGRATION.md); они не описывают доступную функцию текущего выпуска. Актуальные проверки и ограничения приведены в [отчёте 0.6.3](../../docs/TESTING-0.6.3.md); базовые сценарии сохранены в [матрице 0.6.0](../../docs/TESTING-0.6.0.md).

Адаптированный пакет — `ru.drivedeck.headswap`, Activity — `ru.drivedeck.launcher.MainActivity`. У него отдельные данные. Code334 обновляет предыдущую адаптацию с меньшим versionCode при той же подписи, сохраняя её данные. Для связи с HeadSwap оба APK должны быть подписаны **одним ключом**. Устанавливайте обновление из файла либо через **HeadSwap → Настройки → Компоненты HeadSwap Desktop → Установить и обновить компоненты**.

Рабочий DPI встроенных приложений задаётся в HeadSwap. Если коррекция включена для конкретного приложения, она действует в плитке разделённого экрана и при полноэкранном запуске. У остальных приложений сохраняются обычные размеры буфера. Настройка применяется при следующем подключении; старые хосты без запроса конфигурации отдельного пакета сохраняют прежние правила для Карт и Навигатора.

**Системные настройки на ГУ.** Ярлык DriveDeck открывает экспортированную Activity Android «Настройки» на активном рабочем столе HeadSwap. Если прошивка не предоставляет доступного ярлыка, появляется сообщение об ошибке.

Штатные проверки и загрузки обновлений самого DriveDeck отключены: автоматический таймер, ручная проверка, загрузка APK и выбор каналов автора. Сохранены пресеты, сведения устройства, диагностика, обновление погоды и общие HTTP/download-методы. Также отключены функции запуска точки доступа телефона и подключения DriveDeck к аппаратному Bluetooth-контроллеру. Беспроводным CarLife управляет HeadSwap.

## Музыкальный виджет и обложки

В HeadSwap Desktop откройте **Первоначальная настройка → Разрешения → Разрешения DriveDeck** либо ту же кнопку в каталоге компонентов. Разрешите **DriveDeck · HeadSwap** доступ к уведомлениям в системном окне Android. HeadSwap показывает состояние этого доступа и не выдаёт его автоматически. Разрешение HeadSwap для приборной панели не заменяет отдельное разрешение DriveDeck.

После выдачи доступа откройте собственный музыкальный экран DriveDeck через ярлык «Музыка» и запустите плеер. Название, исполнитель и доступная обложка берутся из медиасессии плеера. Для этой функции не нужен доступ к фотографиям или специальным возможностям. Окно отдельного приложения, например Яндекс Музыки, использует собственный интерфейс и не является музыкальным виджетом DriveDeck.

## Кнопки для полноэкранных приложений

В DriveDeck откройте **Настройки → Док → Поведение дока** и включите «Назад в полноэкранных приложениях» или «Домой в полноэкранных приложениях». Изначально обе опции выключены. Они применяются при следующем открытии внешнего приложения во весь экран. Приложение занимает весь экран. Круглые кнопки появляются поверх него в левом нижнем углу. «Домой» возвращает в DriveDeck. Если включены обе кнопки, «Назад» располагается над «Домой» и возвращает на предыдущий экран приложения.

Чтобы одиночный ярлык из дока открывал приложение на весь экран, включите **Настройки → Главный экран → Дополнительные параметры → Одиночные приложения из дока — на весь экран**. Эта настройка выбирает способ открытия ярлыка. Раздел **Док → Поведение дока** управляет видимостью кнопок в уже открытом полноэкранном приложении. При выводе двух приложений рядом DriveDeck использует обычный док.

В текущем комплекте кнопки обслуживает активный HeadSwap Desktop 0.6.3. Он принимает обычный запуск приложения из каталога или дока на текущем дисплее DriveDeck. Встроенные окна продолжают использовать своё управление. Намерения с данными, специальные ссылки, запросы результата и системные действия сохраняют штатный маршрут.

На Android 13 касание встроенного приложения передаёт ему фокус для ввода с экранной клавиатуры. При касании собственных элементов DriveDeck, закрытии окна или выходе из лаунчера фокус возвращается лаунчеру. Клавиатуру на дисплее магнитолы настраивает HeadSwap Desktop.

## Что делает адаптация

- Главный экран совмещает встроенную карту справа и музыкальный виджет, часы и погоду слева. Отдельная страница показывает два настоящих приложения, например навигатор и плеер.
- `TextureView` получает изображение дочернего дисплея, созданного активной службой HeadSwap. Companion не получает shell Binder и не запрашивает собственное разрешение Shizuku. Доступ к ограниченному gateway защищён подписью и проверкой UID; максимум — два дочерних дисплея текущей сессии DriveDeck.
- В code334 касания проходят общий с HeadSwap буфер: новые движения заменяют устаревшие ожидающие движения того же жеста. Начало, окончание и отмена жеста, мультитач и порядок команд сохраняются. Это ограничивает накопление задержки при нагрузке.
- Касания и Back направляются в нужную область. Surface сохраняется до подтверждения закрытия producer либо смерти его отдельного пустого lifetime Binder; опрос состояния приложения выполняется вне UI-потока. После смены страницы прежние области закрываются.
- Сохраняются выбранные приложения и пользовательские макеты. Только точное совпадение со старым стандартным макетом 0.6.7 или адаптации 0.2.0 заменяется новым. Если выбор пуст, настройка использует ранее сохранённые пакеты, затем установленные Яндекс Навигатор/Яндекс Музыку. Обхода всех приложений для случайного выбора нет.
- Удалены HOME/LAUNCHER/ASSIST-регистрация, запрос роли HOME, системный UID, root-команды, автозапуск, телеметрия и изменение общей темы/яркости. Нет overlay-разрешения или `Presentation`. Собственные полноэкранные запуски также остаются на дополнительном дисплее.

Для встроенных приложений нужен активный доступ HeadSwap и поддержка дополнительных дисплеев на телефоне. В HeadSwap 0.6.3 можно активировать доступ с телефона или компьютера; отдельно доступен вариант Shizuku. Доступ необходимо активировать снова после перезагрузки. Это не отдельная Android-система: приложения используют обычные данные и аккаунты, а существующая задача может переместиться с телефона. Защищённые поверхности, несовместимые приложения и особенности прошивки могут ограничивать отображение. Канал звука настраивается отдельно в HeadSwap.

HeadSwap Desktop задаёт DPI действующего рабочего стола встроенным приложениям. При разделении экрана и перемещении разделителя изменяются размеры окна в пикселях, а логический DPI сохраняется. Дополнительное увеличение буфера применяется только к приложениям, выбранным для коррекции DPI.

При возврате в DriveDeck видимым окнам повторно назначаются параметры текущего рабочего стола. Клиент запрашивает их в служебном потоке по идентификатору текущего дисплея. Ответ действует только для того же соединения, окна и активного поколения. Карта проверяет размещение своей задачи перед восстановлением. Для остальных приложений DriveDeck обновляет размер окна с сохранением открытой страницы. Более ранний HeadSwap использует прежние правила code301, включая отдельную обработку Навигатора.

Касания проходят существующее преобразование `render pixels / TextureView pixels` ровно один раз. Изменение буфера и параметров renderer выполняется на UI-потоке, создание/resize — в последовательной очереди Binder. Во время неподтверждённого resize ввод блокируется; потерянный ответ не считается подтверждением старого размера. При capability bit 3 максимум одного буфера — 3840×2160, DPI 1280; HeadSwap ограничивает общий бюджет дочерних дисплеев. Повышенное разрешение увеличивает нагрузку на GPU и память. Изменения не затрагивают APK Навигатора, его настройки или параметры экрана телефона.

Для resize предусмотрены ограниченные повторы: запросы объединяются до последней геометрии, после ошибки выполняются не более трёх повторов через 250, 1000 и 3000 мс. Неизменный layout не сбрасывает этот лимит; новый размер заменяет ожидающий запрос. Запуск приложения ждёт подтверждённого размера, ввод до ACK блокируется. Отправка release повторяется через 500, 1500 и 5000 мс только прежнему gateway и прежнему handle.

Опциональные capabilities расширяют прежний протокол 1: bit 1 — два указателя (`touchPoints`, transaction 9), bit 2 — пустой Binder срока жизни процесса producer (`producerLifetime`, transaction 10). Pointer IDs, action index и координаты копируются из уже преобразованного `MotionEvent`; повторного масштабирования нет. Без bit 1 сохраняется прежний одиночный ввод. Отдельный lifetime Binder не даёт методов, команд или привилегий. После его смерти consumer можно освободить; после обычного release ACK death listener снимается. Смерть общего gateway, тайм-аут или неизвестный результат create не считаются ACK. Если create не вернул handle и lifetime token получить не удалось, потенциально используемый Surface по-прежнему удерживается до безопасного завершения процесса.

Комплект HeadSwap Desktop 0.6.3 рассчитан на Android 13–17. Собственный minSdk companion не расширяет поддержку основного приложения. Успешная компиляция не подтверждает совместимость со всеми прошивками; проверки на устройствах и ограничения указаны в матрице выпуска.

## Пересборка

Команды ниже выполняются из корня репозитория. Нужны Python 3, JDK 17, Android SDK с `platforms/android-37.0` и `build-tools/36.0.0`, стандартный debug keystore с той же подписью, что у HeadSwap, и [Apktool 3.0.3](https://github.com/iBotPeaches/Apktool/releases/tag/v3.0.3). Положите зависимости вне этого каталога. `--work` — отдельная папка результатов; повторная сборка пересоздаёт её `decoded`, `generated-aidl` и каталоги helper-компиляции.

```sh
python3 tools/drivedeck-companion/build.py \
  --original "/path/DriveDeck-0.6.9-code331.apk" \
  --work "/path/companion-build-output" \
  --jdk "/path/jdk17" \
  --sdk "/path/android-sdk" \
  --apktool "/path/apktool_3.0.3.jar" \
  --keystore "/path/headswap-debug.keystore"
```

Поддерживается стандартный debug keystore: alias `androiddebugkey`, стандартный debug-пароль `android`. Ключ не создаётся и не скачивается. Для другой схемы подписи измените signing-команду в своей копии скрипта; пароли и ключи не добавляйте в исходники.

Скрипт проверяет хеш оригинального APK и Apktool, выбирает закреплённый профиль из `profiles.py`, декодирует оригинал, применяет `patch_069.py` для code331, генерирует Java из AIDL и `CompanionSymbols`, проверяет изоляцию штатного обновления приложения, политику геометрии, очередь повторов, условия освобождения Surface, пакеты и буфер касаний, затем компилирует helper-классы, добавляет их DEX, собирает и подписывает APK. Затем проверяет подпись, zipalign и ограничения manifest. Результаты: `DriveDeck-HeadSwap-0.6.9-code334.apk` и `patch-report.json` внутри `--work`. Статус `build: PASS` не означает успешную проверку на телефоне. Бинарная идентичность APK при другой среде или подписи не гарантируется.

## Состав и лицензирование

`profiles.py` выбирает адаптер по SHA-256: `patch_069.py` для 0.6.9 code331, `patch.py` для прежнего 0.6.8 code300. Оба адаптера проверяют ожидаемые smali-фрагменты до изменения. `DisplayOnlyLaunch.java` ограничивает полноэкранные запуски текущим дополнительным дисплеем и переносит стандартный макет. `EmbeddedDisplayClient.java` управляет Surface, Binder-связью, вводом и выбором первоначальных приложений. `EmbeddedRenderProfile.java` подключает общую политику DPI или использует прежние ограничения при работе со старым хостом; `EmbeddedResumeGate.java`, `EmbeddedRetryGate.java`, `EmbeddedSurfaceRelease.java` и `EmbeddedTouchPacket.java` содержат проверяемые правила возврата, повторов, ACK и копирования ввода; общий `shared/com/headswap/desk/shared/MotionDispatchBuffer.java` управляет очередью касаний. Standalone-тесты находятся в `tests/`. `build.py` в этом каталоге отличается от временного скрипта переносимыми обязательными путями; логика адаптации сохранена.

Лицензия HeadSwap находится в [LICENSE](../../LICENSE). Она не определяет права на оригинальный DriveDeck, его ресурсы или торговое название. Исходный APK 0.6.9 получен из стабильного релиза автора. При статическом анализе не выявлен механизм лицензирования/DRM; обход подписки, покупки или проверки права использования в патч не добавлялся. Оригинал остаётся неизменным и не включён в этот каталог.


### Бинарный патч

Скрипт `package.py` упаковывает изменения относительно проверенного оригинального code331. Для выпуска патча требуется Python 3 с `bsdiff4`. После завершения `build.py` выполните:

```sh
python3 tools/drivedeck-companion/package.py \
  --original "/path/DriveDeck-0.6.9-code331.apk" \
  --target "/path/companion-build-output/DriveDeck-HeadSwap-0.6.9-code334.apk" \
  --output "/path/companion-release"
```

В архиве с бинарным патчем находятся программа восстановления и обе контрольные суммы. После распаковки пользователь применяет `apply_patch.py` к оригинальному APK. Программа сверяет SHA-256 результата до записи подписанного файла. Архив исходников содержит адаптер и исходный AIDL.


## Прежний вход 0.6.8

Для воспроизведения старой адаптации сохранён отдельный профиль: оригинальный [DriveDeck 0.6.8 code300](https://github.com/RotkivKiv/DriveDeck-Updates/releases/tag/stable-code300), SHA-256 `bb67e07ff14a6300082a33fa75be2082ab250e5aec1bd6f75e72b5b034b157c4`, адаптер `patch.py`, результат `DriveDeck-HeadSwap-0.6.8-code305.apk`. Для него используется та же команда `build.py` с другим `--original`; профиль определяется содержимым, а не именем файла. Это историческая ветка совместимости, а не APK текущего выпуска 0.6.3. Сборки code304 и ниже остаются предыдущими версиями; они не являются результатом текущей команды.
