# Сборка и подключение HeadSwap Profile SDK v1

Это отдельная Android-библиотека для профилей **HeadSwap 0.5.0**. В AAR входят `ProfileContract`, `ProfileSession`, `ProfileNowPlaying` и сгенерированный Binder-интерфейс. Библиотека не добавляет в манифест разработчика разрешения, Activity или сервисы. APK профиля подписывает его автор.

## Сборка AAR

Требуются JDK 17 и Android SDK Platform 37. `JAVA_HOME` указывает на JDK, `ANDROID_HOME` — на SDK. Из корня репозитория выполните

```sh
./android/gradlew -p sdk/desktop-panel-v1 assembleRelease testDebugUnitTest
```

Для Windows используйте `android\gradlew.bat`. Результат — `sdk/desktop-panel-v1/build/outputs/aar/headswap-profile-sdk-release.aar`. Для сборки без сети можно добавить `--offline`, если Gradle, Android Gradle Plugin 9.4.1 и зависимости тестов уже загружены. Самостоятельная сборка SDK не требует APK HeadSwap, ключей подписи, телефона или AVD.

**Готовый AAR.** Скопируйте файл из ZIP в `app/libs/` проекта профиля. Если собрали AAR самостоятельно, переименуйте его в `headswap-desktop-profile-sdk-v1-dev.aar` для следующего примера. Добавьте в `app/build.gradle.kts`

```kotlin
dependencies { implementation(files("libs/headswap-desktop-profile-sdk-v1-dev.aar")) }
```

**Модуль Gradle из исходников.** Укажите `com.android.library` версии `9.4.1` в настройках плагинов своего проекта, включите модуль в `settings.gradle.kts` и добавьте зависимость в приложение. Здесь `../headswap_desk` — ваша локальная копия репозитория.

В `settings.gradle.kts`

```kotlin
include(":desktop-panel-sdk")
project(":desktop-panel-sdk").projectDir = file("../headswap_desk/sdk/desktop-panel-v1")
```

В `app/build.gradle.kts`

```kotlin
dependencies { implementation(project(":desktop-panel-sdk")) }
```

Используйте один вариант зависимости. AIDL-заглушки уже находятся в `classes.jar`. Если ранее вы копировали `IDesktopPanelSession.aidl` в приложение, удалите эту копию перед подключением библиотеки. Минимальная версия Android — API 33.

## Получение сеанса

Объявите Activity профиля по [руководству SDK](README.md). В `onCreate` получите текущую сессию. В `onNewIntent` замените её целиком, включая случай автономного запуска.

```java
private ProfileSession session;

@Override protected void onCreate(Bundle state) {
    super.onCreate(state);
    session = ProfileSession.from(getIntent());
}

@Override protected void onNewIntent(Intent intent) {
    super.onNewIntent(intent);
    setIntent(intent);
    session = ProfileSession.from(intent);
}
```

Импортируйте `com.headswap.desk.component.api.ProfileSession`. Публичные именованные константы находятся в `ProfileContract` из того же пакета. После обычного запуска через системный launcher `from` вернёт `null`. Автономный интерфейс и собственные настройки профиля могут продолжать работу.

При нажатии пользователем на ярлык вызовите `session.requestLaunch(componentName)` с точной публичной `MAIN`/`LAUNCHER` Activity либо `session.openCatalog()` для открытия каталога HeadSwap. Перед показом кнопок проверьте `session != null` и `canLaunchApps()` / `canOpenCatalog()`. Результат `true` означает, что хост принял запрос к обработке. `false` возможен после отзыва сессии, при неподходящей цели и при потере Binder. Хост повторно проверяет подписанта, UID, целевой компонент и текущее окно. Не сохраняйте Binder между запусками и не передавайте его другим процессам. Обычный Intent может прийти от любого приложения и не подтверждает личность отправителя.

## Собственная оболочка и нижняя панель

Профиль может рисовать свой рабочий стол, док, избранное и меню в обычной Android Activity. Для размещения над ней отдельного окна карт, которым управляет HeadSwap, добавьте **оба** логических признака к этой Activity.

```xml
<meta-data android:name="com.headswap.desk.component.DASHBOARD" android:value="true" />
<meta-data android:name="com.headswap.desk.component.PROFILE_CHROME" android:value="true" />
```

При наличии `session.canUseProfileChrome()` передавайте состояние интерфейса одним вызовом `setDashboardLayout(musicVisible, musicOnRight, targetVisible, dockHeightPx)`. Первые два аргумента определяют видимость музыкальной зоны и её сторону. Когда зона показана, она занимает 30 % ширины. Над оставшейся областью HeadSwap располагает приложение, например навигатор. Последний аргумент сообщает измеренную высоту авторского дока в пикселях дисплея Activity. Хост начинает с 39 dp, принимает ноль для автоскрытия и ограничивает занимаемое место меньшим из 96 dp и 20 % высоты. Работайте в фоновом потоке, передавайте только изменившееся состояние. Если вызов вернул `false` во время открытия, повторите **последнее** состояние после появления окна.

Для собственного домашнего экрана, списка избранного, шторки или собственных полей ввода передайте `targetVisible=false`. Авторская Activity снова получает всю область. Затем передайте `true`, чтобы вернуть уже открытое приложение. Фокус и ввод внутри авторских полей обслуживает Android IME. Команды `sendDashboardAction(ProfileContract.DASH_BACK)`, `DASH_NAVIGATION` и `DASH_PHONE_TOGGLE` предназначены для нажатий на видимом доке. HeadSwap проверяет действующий сеанс и сам выбирает управляемое окно. Произвольные коды клавиш, текст для чужого окна и идентификаторы дисплеев в эти методы передать нельзя. При открытии собственного домашнего экрана сохраните нужное состояние через `setDashboardLayout`. Вызов `openCatalog()` относится к каталогу самого HeadSwap.

Выбор приложения навигации хранит сам автор профиля. По нажатию в собственном списке вызовите `requestLaunch(componentName)` с точной экспортируемой `MAIN/LAUNCHER` Activity или её публичным псевдонимом. Для своей оболочки допускается запрос приложения с `singleTask`. Если Android может переместить уже открытое окно телефона, решение принимает пользователь в диалоге HeadSwap. Обычные однооконные панели по-прежнему используют приложения с независимой задачей. Без указанной цели `DASH_NAVIGATION` ведёт в общий каталог. Когда авторская панель целиком закрыта приложением, команды управления блокируются. Через `setDashboardLayout` можно вновь раскрыть собственный интерфейс.

## Активный трек и управление воспроизведением

Музыкальная панель объявляет доступ к медиавозможности следующим элементом внутри **своей Activity**. Если он уже включён для авторской оболочки, дублировать его не нужно.

```xml
<meta-data android:name="com.headswap.desk.component.DASHBOARD" android:value="true" />
```

При выборе профиля пользователь отдельно решает, передавать ли ему сведения о текущем треке и разрешать ли кнопки плеера. Новая установка и старое доверие к подписи сами по себе этой возможности не дают. В HeadSwap должен быть включён системный доступ к медиасессиям, например через уже настроенный доступ HeadSwap к уведомлениям. Android-разрешения для APK панели не нужны.

В открытой музыкальной зоне опрашивайте SDK в рабочем потоке, например один раз в две секунды. Переносите обновление собственного UI на главный поток. Останавливайте таймер и очищайте трек при скрытии зоны, завершении Activity или получении `null`. Обложка необязательна даже у доступного трека.

```java
if (session != null && session.canUseMedia()) {
    ProfileNowPlaying track = session.getNowPlaying();
    // При track == null покажите пустое состояние. Иначе доступны
    // getTitle(), getArtist(), isPlaying() и getArtwork().
}
// Выполнять по нажатию в панели, тоже в рабочем потоке.
boolean sent = session != null && session.sendMediaCommand(ProfileContract.MEDIA_PLAY_PAUSE);
```

`MEDIA_PREVIOUS`, `MEDIA_PLAY_PAUSE`, `MEDIA_NEXT` применяются только к поддерживаемым действиям текущего локального плеера. Результат `false` означает, что команду не отправили. Хост сверяет UID, подпись, выбранный профиль, согласие и видимость его музыкальной зоны при каждом вызове. Для обложки возвращается уменьшенная копия до 192 × 192 пикселей. Изображение и подписи предназначены для текущего кадра. Если нужен живой навигатор, его окно размещает HeadSwap в отдельной области проекции.

## Резерв для микрофона и голосового канала

`CAP_MICROPHONE_INPUT` и `CAP_VOICE_CHANNEL` обозначают две отдельные возможные функции. В текущем SDK для них нет команд. `canUseMicrophone()` и `canUseVoiceChannel()` возвращают `false`. `supports(bit)` принимает один реализованный бит. Нулевое значение, объединение нескольких битов, неизвестные и зарезервированные биты дают `false`, даже если отправитель включил их в маску.

Для будущей реализации потребуется отдельное согласие пользователя на конкретную сессию и источник звука. До передачи хост согласует направление потока, формат, владельца микрофона, аудиофокус и приоритет текущей голосовой операции. При блокировке, отключении ГУ или отзыве разрешения хост прекращает захват, закрывает канал и инвалидирует выданный доступ. Содержимое аудио не пишется в отчёты. Навигационные подсказки и метаданные медиаплеера остаются отдельными возможностями. Само объявление бита не включает запись или передачу звука.

[Сборка собственного APK из распакованного SDK](DEVELOPER-GUIDE.md). Комплект также содержит исходники самой библиотеки: `./gradlew -p sdk-source assembleRelease testDebugUnitTest`.
