# SDK v1 для независимого профиля HeadSwap

**Локальная версия для разработки — HeadSwap Desktop 0.5.0-dev, Android 13+.** Автор поставляет собственный APK, подписывает его своим ключом и сам определяет интерфейс, настройки и функции лаунчера. Пользователь выбирает его через **«Профиль» на главном экране**. Название **CarBridge** относится к отдельной записи в этом списке. Все независимые профили v1 работают на движке Android Desktop. У HeadSwap остаются родительский экран, боковая панель, «Домой», «Назад», реальные окна приложений, ввод, CarLife и HUD.

## 1. Зарегистрировать лаунчер

Укажите своё стабильное имя пакета и отдельную экспортированную Activity. Имя класса входит в идентификатор профиля. Для CarBridge автор объявляет `MODE_ID=carbridge`; остальные авторы выбирают свои значения. Допустимы строчные латинские буквы, цифры, точка, дефис и подчёркивание, всего до 64 знаков. Одинаковое имя режима в двух APK не объединяет их подписи. Если установлены два адаптера CarBridge, пользователь выбирает точный компонент. Название и иконка приложения сами по себе не подтверждают издателя.

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <!-- Нужно, только если лаунчер предлагает список установленных приложений. -->
    <queries>
        <intent>
            <action android:name="android.intent.action.MAIN" />
            <category android:name="android.intent.category.LAUNCHER" />
        </intent>
    </queries>
    <application android:label="Мой лаунчер">
        <activity android:name=".PanelActivity" android:label="CarBridge"
            android:exported="true" android:resizeableActivity="true"
            android:launchMode="standard">
            <intent-filter>
                <action android:name="com.headswap.desk.action.DESKTOP_COMPONENT" />
                <category android:name="android.intent.category.DEFAULT" />
            </intent-filter>
            <meta-data android:name="com.headswap.desk.component.API_MAJOR" android:value="1" />
            <meta-data android:name="com.headswap.desk.component.PROFILE" android:value="android-desktop" />
            <meta-data android:name="com.headswap.desk.component.MODE_ID" android:value="carbridge" />
        </activity>
    </application>
</manifest>
```

Вход панели поддерживает `standard` или `singleTop`. Оставьте обычный режим документов и выключенный перенос задач. Если автор также выпускает самостоятельный телефонный продукт, выделите панели отдельную Activity или установите отдельный APK. Для работы профиля достаточно указанного фильтра, без регистрации как системный `HOME` или обработчик USB.

## 2. Подключить контракт

Самый быстрый путь — скопировать поставляемый **`headswap-desktop-profile-sdk-v1-dev.aar`** в `app/libs/` своего Android-проекта и добавить зависимость в `app/build.gradle.kts`. Установка SDK как отдельного приложения на телефон не требуется.

```kotlin
dependencies {
    implementation(files("libs/headswap-desktop-profile-sdk-v1-dev.aar"))
}
```

Для получения полностью самостоятельного проекта используйте ZIP локального SDK. [Сборка библиотеки и подключение AAR](BUILDING.md). При разработке внутри репозитория вместо AAR можно подключить Gradle-проект библиотеки. Выберите один из этих путей, чтобы в APK не было дублирующихся классов. [Исходники профиля и Gradle-настройки](../../examples/android-desktop-panel/README.md) · [Исходный AIDL v1](src/main/aidl/com/headswap/desk/component/api/IDesktopPanelSession.aidl).

HeadSwap сам создаёт дочернее окно, открывает в нём Activity выбранного профиля и передаёт дескриптор текущего сеанса. Получите клиент из Intent Activity. При повторном Intent используйте новый клиент; не сохраняйте Binder между запусками. Ниже `target` — точный `ComponentName` из результата `MAIN/LAUNCHER` для выбранного пользователем ярлыка.

```kotlin
// Поле Activity. Закройте executor в onDestroy().
private val worker = java.util.concurrent.Executors.newSingleThreadExecutor()

// В обработчиках текущей Activity session — клиент из ProfileSession.from(intent).
openAppButton.setOnClickListener {
    val current = session ?: return@setOnClickListener
    worker.execute {
        if (!current.requestLaunch(target)) runOnUiThread {
            showStatus("Откройте профиль снова или выберите другое приложение")
        }
    }
}
allAppsButton.setOnClickListener {
    val current = session ?: return@setOnClickListener
    worker.execute { current.openCatalog() }
}
```

`true` означает, что запрос принят для дальнейшей проверки открытого окна. Хост сверяет UID, текущий сеанс, подписанта и доступность целевой Activity. Для запуска у неё должен быть экспортируемый вход MAIN/LAUNCHER без специального разрешения. SDK принимает цели с режимом `standard` или `singleTop`, обычным режимом документов и без переноса Activity между задачами. Запрос для цели с `singleTask` отклоняется, поскольку её окно может уже быть открыто на телефоне. Выход из панели или закрытие USB-сеанса отзывает дескриптор. В своей Activity можно свободно рисовать интерфейс и реализовывать свои функции обычными средствами Android.

### Микрофон и голосовой канал

В SDK отдельно зарезервированы `CAP_MICROPHONE_INPUT` и `CAP_VOICE_CHANNEL`. В 0.5.0-dev `canUseMicrophone()` и `canUseVoiceChannel()` возвращают `false`. Отдельные флаги нужны потому, что получение звука микрофона и наличие голосового маршрута у ГУ — разные условия. SDK v1 не объявляет разрешение на запись, не записывает звук и не открывает аудиопоток. Профиль может показывать собственные голосовые действия только при доступной в будущих версиях возможности. Отдельное согласие, выбор источника и направления, аудиофокус, отзыв при завершении сеанса и политика для звонков должны быть определены до добавления аудиометодов.

## 3. Установить и выбрать профиль

Установите APK автора системным установщиком Android. Пока соединение с ГУ остановлено, на главном экране HeadSwap нажмите **«Профиль»**, выберите нужное имя и проверьте пакет, Activity, версию и SHA-256 сертификата. Нажмите **«Использовать»**. Затем подключитесь к CarLife. HeadSwap сохраняет выбор в текущем Android-пользователе. Кнопка «Домой» на ГУ открывает каталог HeadSwap. Для повторного открытия внешнего интерфейса служит кнопка панели в каталоге.

Если в списке видно **«CarBridge · не установлен»**, установите APK с контрактом выше. Самостоятельный CarBridge Offline v0.43 не объявляет этот вход. Для локальной проверки подготовлены обычная демонстрационная панель и отдельный тестовый адаптер со своей подписью для профиля CarBridge. Они написаны в этом проекте и не содержат оригинального кода CarBridge. [Исходники и проверка примера](../../examples/android-desktop-panel/README.md).

## 4. Выпускать обновления независимо

Сохраняйте `applicationId`, имя Activity, `MODE_ID` и ключ издателя. Увеличивайте `versionCode`, выпускайте APK своим каналом и устанавливайте обновление поверх предыдущего. Новые экраны, сетка, избранное и панели внутри собственной Activity могут поставляться без обновления HeadSwap. При изменении подписанта или идентичности профиля требуется новый явный выбор. Закрытый ключ никому передавать не нужно. Прототип обнаруживает установленные APK. Встроенный загрузчик версий для сторонних профилей и подписанный реестр издателей относятся к следующему этапу.

## 5. Что проверить перед передачей пользователю

- Профиль виден на главном экране, при выборе указаны его пакет и сертификат. Android Desktop и DriveDeck без этого APK запускаются как обычно.
- Появляются родительский экран и кнопки HeadSwap, а в рабочей области — UI автора. Откройте приложение из сетки автора и вернитесь к каталогу через «Домой». Код профиля не запрашивает общий ключ HeadSwap, права USB или беспроводную отладку.
- Измените размер собственной панели и проверьте попадание касаний. Основной экран телефона сохраняет DPI. При уходе на «Домой», смене пакета или отключении USB запрос со старым дескриптором не должен открыть приложение.
- Сбой, удаление или несовместимое обновление панели возвращают пользователю штатный каталог. Профиль с неизвестным major API не предлагается. Действующая проекция не должна входить в цикл перезапусков.

Разделение экрана с чужим навигатором и реальной музыкой потребует дополнительного контракта компоновки. В тестовой панели 70/30 меняет расположение её собственных элементов. [Границы и план SDK](../../docs/DESKTOP-COMPONENT-API.md).
