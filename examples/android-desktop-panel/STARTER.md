# Полноэкранный профиль Android Desktop

Вариант `starter` показывает минимальный рабочий стол с собственным нижним рядом кнопок. В проекте две части. `PanelActivity.java` устанавливает связь с HeadSwap через публичный SDK и управляет её временем жизни. `StarterScreen.java` строит интерфейс и получает список доступных ярлыков приложений через Android. Пример самостоятельно разработан для HeadSwap.

### Собрать и установить

Из корня распакованного комплекта SDK с JDK 17, Android SDK Platform 37 и Build Tools 36.0.0 выполните команду для вашей ОС.

```sh
./gradlew :app:assembleStarterDebug
```

```bat
gradlew.bat :app:assembleStarterDebug
```

Установите `app/build/outputs/apk/starter/debug/app-starter-debug.apk` в тот же Android-профиль пользователя, что и HeadSwap Desktop 0.5.0. Откройте **Профиль → Стартовый рабочий стол**, сверьте издателя и подтвердите выбор. Для испытания трека дайте отдельное согласие на музыку. Откройте сеанс ГУ. В исходном репозитории вместо команды выше используйте `./android/gradlew -p examples/android-desktop-panel :app:assembleStarterDebug`.

| Идентификатор | Значение |
|---|---|
| APK | `com.example.headswap.panel.starter` |
| Activity | `com.example.headswap.panel.PanelActivity` |
| MODE_ID | `open-dashboard-starter` |
| Класс клиента SDK | `com.headswap.desk.component.api.ProfileSession` |

### Проверить на ГУ

1. На главном экране выберите установленное приложение по имени и пакету. Его окно откроет HeadSwap рядом с панелью. Для приложения с единственным окном Android хост может запросить подтверждение переноса с телефона.
2. Нажмите **Домой**. Отобразится собственный список профиля. **Каталог ГУ** откроет штатный каталог HeadSwap. **Назад** передаёт запрос активному окну.
3. Нажмите **Музыка**, чтобы скрыть или вернуть карточку, и **Сторона**, чтобы поменять стороны. При согласии на музыку и активном плеере карточка покажет настоящий трек. Кнопка **Пуск / пауза** отправит запрос плееру.
4. Завершите сеанс и подключитесь повторно. Activity получит новый объект `ProfileSession`. При недоступности сеанса на экране есть пояснение. **Домой** повторяет проверку после восстановления связи.

### Адаптировать

В каталоге `app/src/starter` лежат Activity, интерфейс и дополнительные метаданные `DASHBOARD` и `PROFILE_CHROME`. Основные действие, категория и версия API объявлены в `app/src/main/AndroidManifest.xml`. При создании собственного приложения задайте уникальные `applicationId`, `MODE_ID` и отображаемое имя. Запишите имя Activity и сохраняйте подписывающий ключ для обновлений.

После появления Activity на дочернем дисплее вызовите `setDashboardLayout(musicVisible, musicOnRight, targetVisible, dockHeightPx)`. Пример сообщает измеренную высоту своего дока в физических пикселях текущего окна. При `targetVisible = false` HeadSwap раскрывает интерфейс автора, сохраняя уже запущенную задачу. Пока первый кадр ещё не появился, хост может отклонить запрос. Пример несколько раз повторяет актуальную компоновку и предлагает ручной повтор.

Для запуска Activity передаётся точный `ComponentName` из результатов запроса `MAIN/LAUNCHER`. Возвращённое `true` означает постановку запроса в очередь. Размещение приложения подтверждает хост. Все вызовы выполняются в рабочем потоке. После `onStop` приложение прекращает опрос плеера, а результаты старых запросов отбрасывает.

Пригодность каждой операции проверяется отдельно через `canUseProfileChrome()`, `canLaunchApps()`, `canOpenCatalog()` и `canUseMedia()`. Для карточки музыки достаточно согласия пользователя в HeadSwap. Профиль не запрашивает Android-разрешений и не добавляет виртуальные дисплеи, USB-обработчики или фоновые службы.
