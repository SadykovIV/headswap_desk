# Панель Android Desktop

Локальный пример для разрабатываемого HeadSwap Desktop **0.5.0**, API v1. У него самостоятельный пакет `com.example.headswap.panel`, своя версия `1.0` и одна экспортируемая `.PanelActivity`. Она отображает ID и геометрию своего окна, плотность ресурсов Activity и счётчик нажатий. Справа находится заметка шириной 30% окна. Её можно перенести влево, скрыть и вернуть; компоновку рисует APK автора. Это локальный образец интерфейса, без музыкальных или маршрутных данных. Пример объявляет собственную точку входа и запрос видимости ярлыков Android. Кнопка «Открыть приложение» показывает локальный каталог и отправляет выбранные пакет и Activity через сессионный Binder. Проект подключает публичную Android-библиотеку SDK v1. Возможности микрофона и голосового канала предусмотрены контрактом на будущее. Панель показывает их недоступность в этой версии хоста, не запрашивает разрешение на микрофон и не начинает запись. Разрешений, USB-фильтра, фоновых служб и зависимости от закрытого интерфейса HeadSwap у него нет.

## Собрать

Из корня репозитория на машине с JDK 17 и Android SDK Platform 37:

```sh
./android/gradlew -p examples/android-desktop-panel :app:assembleExampleDebug
```

Результат — `examples/android-desktop-panel/app/build/outputs/apk/example/debug/app-example-debug.apk`. Этот APK предназначен для локальной разработки. Для собственного продукта задайте уникальный пакет, выпускайте его под своим постоянным ключом и определяйте совместимость по версии API, заявленной в манифесте. Для проверки независимости издателей подпишите пример ключом, отличным от ключа хоста; при сборке APK на одной машине стандартный debug-ключ у разных проектов часто общий.

Также предусмотрен flavor `carbridgePreview`. Соберите его командой `./android/gradlew -p examples/android-desktop-panel :app:assembleCarbridgePreviewDebug`. Его APK находится в `app/build/outputs/apk/carbridgePreview/debug/app-carbridgePreview-debug.apk` внутри каталога примера. У него отдельный пакет `com.example.headswap.panel.carbridgepreview`, отображаемое имя «Тестовая панель HeadSwap для CarBridge» и `MODE_ID=carbridge`. Это локальная тестовая реализация команды HeadSwap с исходниками этого примера, не официальный APK автора CarBridge и не перенос его ресурсов. Flavor проверяет появление профиля «CarBridge» и работу собственного интерфейса. Оба примера можно поставить рядом.

Тот же пример можно собрать с отдельным бинарным AAR вместо проекта SDK. Передайте абсолютный путь в `-PdesktopPanelSdkAar=/путь/к/sdk.aar` той же команде Gradle.

## Проверить

Установите HeadSwap Desktop 0.5.0 и APK примера в одном Android-профиле. На главном экране откройте список «Профиль», выберите «Демо-панель», сверьте предлагаемые пакет, Activity и SHA-256 сертификата и нажмите «Использовать». Она запускается на движке Android Desktop. Подключите ГУ. Родительский дисплей и боковая панель принадлежат HeadSwap. Внутри должно открыться окно примера с положительным ID дисплея. Нажмите «Проверить касание», перенесите или скройте заметку. Нажмите «Открыть приложение», выберите установленный ярлык, затем вернитесь к штатному интерфейсу с помощью элементов хоста. При выключении или удалении выбранного компонента должен остаться доступен встроенный рабочий стол.

Обычный пример для HeadSwap Desktop 0.4.1 с Android-фильтром `MAIN/LAUNCHER` находится [в отдельном проекте](../component-activity/README.md). [Контракт панели](../../docs/DESKTOP-COMPONENT-API.md).

## Создать собственный режим

1. Задайте свой постоянный `applicationId`, полное имя Activity и отображаемое имя. Для адаптера автора CarBridge это может быть «CarBridge». Опубликуйте его под собственным ключом и увеличивайте `versionCode` при обновлениях.
2. На экспортируемой и изменяемой по размеру Activity сохраните действие `com.headswap.desk.action.DESKTOP_COMPONENT`, категорию `android.intent.category.DEFAULT` и метаданные `com.headswap.desk.component.API_MAJOR=1`, `com.headswap.desk.component.PROFILE=android-desktop`. Задайте стабильный `com.headswap.desk.component.MODE_ID`: в примере `example-panel`, для авторского адаптера возможен `carbridge`. Имя определяет надпись для пользователя в списке профилей главного экрана, а ID обозначает режим внутри пакета.
3. Подключите [SDK v1](../../sdk/desktop-panel-v1/README.md) и получите `ProfileSession.from(intent)` в `onCreate` и `onNewIntent`. Когда `canLaunchApps()` вернул true, передайте выбранный `ComponentName` публичной `MAIN/LAUNCHER` Activity в `requestLaunch`. Для возврата в штатный каталог проверьте `canOpenCatalog()` и вызовите `openCatalog()`. Если сессия недоступна либо запрос отклонён, оставьте UI панели работоспособным. Значение true подтверждает приём запроса, а не размещение чужой Activity.
4. Отрисуйте собственный интерфейс внутри Activity. Компонент может менять расположение своих элементов. Выбор приложения из списка направляется хосту через подтверждённую сессию. Системные «Назад» и «Домой», запуск выбранной задачи, дисплей и транспорт остаются в ведении хоста. Собственная компоновка 70/30 не создаёт второе окно Android и не даёт доступ к управлению чужими приложениями или медиасессиями.
5. Пользователь устанавливает APK, сверяет пакет/сертификат и выбирает его через «Профиль» главного экрана. Совместимое обновление выпускайте с прежним package, классом, ID режима и сертификатом.

Демо-панель написана специально для этого примера. Опубликованный самостоятельный APK CarBridge v0.43 не объявляет такой адаптер. [План для автора CarBridge](../../docs/CARBRIDGE-PILOT.md).
