# Пример «Дисплей HeadSwap»

Небольшое Android-приложение с отдельным пакетом `com.example.headswap.displayinfo`. Его можно открыть на телефоне или из списка приложений **Android Desktop** в HeadSwap Desktop 0.4.1. Оно показывает ID дисплея, плотность из ресурсов Activity в DPI и текущий размер своего окна в пикселях. Кнопка считает нажатия и сохраняет результат при пересоздании Activity.

У приложения одна стандартная точка входа `MAIN/LAUNCHER`. В 0.4.1 этот APK открывается отдельным окном на рабочем столе. Выбор стороннего APK в качестве самого рабочего стола относится к предложенному API компонентов.

## Сборка и установка

Понадобятся JDK 17, Android SDK с платформой API 37 и Build Tools 36.0.0. Укажите путь к JDK в `JAVA_HOME`, путь к SDK в `ANDROID_HOME`. Выполните команду из каталога этого примера.

```sh
../../android/gradlew -p . :app:assembleDebug
```

В Windows используйте wrapper для командной строки.

```bat
..\..\android\gradlew.bat -p . :app:assembleDebug
```

Готовый файл — `app/build/outputs/apk/debug/app-debug.apk`. Gradle подписывает его отладочным ключом разработчика. Для публикации своего приложения задайте уникальный `applicationId` и используйте собственный постоянный ключ выпуска.

```sh
adb devices -l
adb -s SERIAL install -r app/build/outputs/apk/debug/app-debug.apk
```

Вместо `SERIAL` подставьте идентификатор своего тестового устройства из первой команды.

## Проверка в HeadSwap

1. На телефоне запустите «Дисплей HeadSwap» из списка приложений. Основной дисплей имеет ID 0. Нажмите «Проверить нажатие».
2. В HeadSwap выберите **Android Desktop**, активируйте доступ и подключитесь к CarLife. На головном устройстве откройте список приложений и выберите «Дисплей HeadSwap».
3. В окне на ГУ должен появиться ID дополнительного дисплея, отличный от 0. Нажатие в этом окне должно изменить его счётчик. Числовой ID может измениться после отключения и повторного запуска.
4. Чтобы проверить изменение DPI, остановите сеанс, выберите другое значение в **Настройки → Изображение на магнитоле**, затем подключитесь снова. Для проверки базового DPI оставьте этот пример вне списка **Исправить DPI приложения**. У приложения из этого списка Android может показывать повышенную плотность внутреннего буфера.

Проверяемая Activity использует собственный контекст и прикреплённое окно. Ей не нужны права на USB, ADB, ввод или экран телефона. [Инструкция по подключению HeadSwap](../../INSTALL.md)

## Результат контрольного запуска

На отдельном эмуляторе Android 17 / API 37 пример собран с сертификатом, отличным от сертификата опубликованного HeadSwap 0.4.1 (код 35). Из штатной сессии Android Desktop тестовый CarLife-клиент передал нажатие на ярлык боковой панели. `DisplayInfoActivity` стала активной на дочернем дисплее №4 при 128 DPI. Родительский дисплей №3 имел 1280 × 720 и 128 DPI, получено 92 видеокадра. Основной дисплей оставался на 420 DPI до запуска, во время сеанса и после отключения. Проверка выполнялась по TCP на тестовом стенде. Номера дисплеев относятся только к этому прогону.
