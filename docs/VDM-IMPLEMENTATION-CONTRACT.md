# Контракт интеграции VDM для 0.6.0

Работа продолжается после локального checkpoint `a3438e6`. Публикации нет. Положительный эксперимент API37 с настоящим PIN подтверждён; интеграция в рабочий сеанс ещё выполняется.

## Выбранная архитектура

VirtualDevice и все его VirtualDisplay принадлежат отдельному UID2000 host. Приложение использует узкий Binder-интерфейс, а не передаёт управление shell-owned дисплеями через недокументированное меж-UID использование callback tokens. Экспериментальный заранее выделенный пул не используется: он усложняет очистку задач и подтверждение освобождения Surface и расходится с same-UID контрактом API.

Один host обслуживает не более одного активного producer/session. Новый сеанс получает отдельный Binder capability. Родитель и все его дочерние дисплеи принадлежат одному VirtualDevice и одной проверенной ненулевой группе. Обычные дисплеи нельзя незаметно подмешивать при ошибке VDM.

## Разделение интерфейсов

- `IVdmDesktopHost`: версия протокола; открытие сеанса с producer lifetime Binder; проверка принадлежности display ID; остановка host. Host принимает только UID нашего приложения либо shell для подтверждённого внутреннего backend.
- `IVdmDesktopSession`: create/resize/release дисплея, проверка группы, close. Session binder служит native-producer lifetime: он расположен в host. Повторный close/release идемпотентен; устаревший capability не управляет новым сеансом.
- `VdmHostProvider` / `VdmHostLink`: передача host только от UID2000 с одноразовым nonce текущего живого активированного приложения; новый host не заменяет живой без явного закрытия. Nonce не попадает в журналы.
- `OwnedDesktopDisplay`: одинаковый интерфейс локального и VDM display — display/id/resize/release и native-producer lifetime. Бизнес-логика окон и input protocol17 сохраняется.

## Владение и завершение

Успешный release/close подтверждается после native VirtualDisplay.release. При смерти producer host закрывает весь его сеанс и завершается: смерть локального `:delegated` сама по себе не выдаётся за смерть native owner. Коннектор и registry следят за native lifetime, чтобы не освобождать Surface раньше подтверждения производителя.

Проверка ввода/IME разрешает shell-owned display только при подтверждённой принадлежности текущему authenticated host и текущему producer generation. Произвольные дисплеи shell или оригинального HeadSwap не принимаются.

## Активация и восстановление

VDM bootstrap использует штатный CDM `associate` с проверкой фактических package/profile/MAC/ID. Проверяется настоящий синтаксис команды; synthetic restore не используется. У HeadSwap Desktop отдельный идентификатор привязки. Удаляются только собственные записи; чужие association/роли не сбрасываются.

Рабочий путь активации с телефона и RemoteInput сохраняется. Подготовка VDM выполняется после готовности активированного процесса. Восстановление host должно быть ограниченным по времени и привязанным к живому сеансу; прекращение пользователем останавливает повторные попытки. Зависимость от USB-debug/mDNS/ADB TCP проверяется отдельно. Изменение постоянного режима adbd нельзя скрывать как обычное восстановление процесса.

## Проверки

1. Настоящий main APK: родитель и два дочерних окна в ненулевой VDM группе, новые кадры и касания после PIN-блокировки телефона.
2. Обычный Back, клавиатура, два окна, Home и DPI после перехода на VDM.
3. Закрытие child/session, смерть producer и смерть host: нет ложного ACK, утечки задач, Surface или использования старого capability.
4. Повторное подключение, восстановление host и отмена ожидания. Физический USB Samsung остаётся отдельной ручной проверкой.
5. Регрессии Android13–16 с прежним локальным backend.
