# Активация и первоначальная настройка

Реализация основана на актуальной HeadSwap Desktop 0.5.1. Сопоставлен оригинальный HeadSwap `8ab72c8846e7777ac355ae6260ab1ce78cba0af4`, файлы `dex/PhoneActivationService.kt`, `dex/PhoneAdb.kt`, `ui/Readiness.kt`.

## Изменения

- В списке беспроводной отладки новое сопряжение называется `headswap-desk`. Ключ остаётся в приватных данных `com.headswap.desk`, зашифрованным ключом Android Keystore. Ключ оригинального приложения недоступен и не используется. Уже сохранённое сопряжение не удаляется при обновлении. Для изменения старой подписи записи Android требуется явно выполнить «Сопрячь заново».
- Сопряжение и активация выполняются в отдельной foreground-службе `PhonePairingService`. Системное окно с кодом остаётся открытым. Высокоприоритетное уведомление содержит три коротких шага и кнопку «Ввести 6 цифр». Пробелы при вставке допустимы, код проверяется как шесть ASCII-цифр. Ответы Android не дают приложению универсально задать цифровую клавиатуру, поэтому формат валидируется после ввода.
- Ответ относится только к текущей попытке. Для него используется явный mutable PendingIntent на неэкспортированную службу и случайный идентификатор попытки. Старые ответы и повторы во время проверки не выполняют новую операцию. Сам код не записывается в файл, состояние Activity или журнал, уведомление не повторяет введённые цифры.
- Отдельные уведомления для ожидания и кода. После отправки кода сразу убирается индикатор ответа SystemUI. Ошибку можно исправить в новом ответе. Ввод ограничен пятью минутами, обнаружение порта и сетевые соединения имеют собственные сроки. Отмена закрывает поиск и прекращает ожидание. После передачи запуска Android результат проверяется существующим протоколом `PhoneActivationStatus`.
- Механизм активации сохранён. Служба использует `DexAccess`, проверяет собственный адрес и существующую локальную установку с nonce, запускает тот же launcher. Уведомление не принимает команды, адреса или набор привилегий.
- При отказе в уведомлениях остаётся ручной ввод в разделённом экране. Разрешение локальной сети запрашивается только при необходимости на Android 17+.
- Первоначальная настройка состоит из трёх экранов. Уведомления и исключение из оптимизации батареи запрашиваются отдельными кнопками, далее доступны компоненты и инструкция активации. Шаги можно пропустить или открыть повторно в настройках. Имеющееся сопряжение не заставляет проходить настройку заново.
- На главном экране добавлен выбор USB / Wi-Fi CarLife и переход к настройке беспроводной магнитолы. Активация ADB и транспорт CarLife остаются отдельными действиями.
- Настройки скорости показывают Мбит/с вместо фиксированной частоты. Добавлены независимые переключатели автоматического возобновления музыки и шторки уведомлений. Шторка по умолчанию выключена.

## Проверки

Модульные тесты `PairingReplyPolicyTest` проверяют формат кода, отклонение старого ответа, одноразовое окно ввода и публичную идентичность. `DesktopPrefsTest` проверяет миграцию и сохранение новых настроек.

Для проверки на настоящем телефоне нужны новое сопряжение при открытых системных настройках, ошибка кода и повторный ввод, отмена, отказ в разрешении уведомлений, завершение после перезапуска активируемого процесса. Доступность Bluetooth/Wi-Fi Direct и поведения OEM при экономии батареи проверяется отдельно от эмуляторной компиляции.

## Шторка уведомлений на ГУ

- Отображается ограниченным окном `TYPE_APPLICATION_OVERLAY` на текущем родительском виртуальном дисплее. Не создаётся на дисплее 0, не следует за посторонним монитором и удаляется при потере живого сеанса или разрешения.
- Стандартное разрешение Android «Поверх других приложений» включается пользователем после объяснения. Подмена системных trusted-флагов, спецвозможности и перехват чужих Activity не используются. Разрешение не выдаётся ADB-командой конечному пользователю автоматически.
- Шторка работает независимо от Activity профиля, в том числе поверх DriveDeck и внешнего компонента. Свёрнутый язычок занимает только свою область. Открывается нажатием или жестом вниз. Развёрнутая шторка показывает максимум 50 текущих уведомлений, позволяет убрать запись или очистить список.
- Сохранена фильтрация оригинала `launcher/NotificationsLogic.kt` (GPL-3.0, `8ab72c8`). Пропускаются собственные, постоянные и неубираемые записи, сводки групп, звонки и плееры. Принимаются только уведомления текущего Android-пользователя. Текст ограничен по размеру, хранится только в памяти активного сеанса. После отключения модель очищается.
- Если телефон заблокирован, тексты всех карточек скрываются, даже если экран ГУ независим от блокировки. Нажатие на карточку не запускает непрозрачный PendingIntent на телефоне. Специальные содержимое, ключи, отправители и тексты не пишутся в журналы.
- `HuShadePolicyTest` покрывает разрешения, принадлежность дисплея, скрытие текста при блокировке и ограниченный список. `NotificationShadeProbe` предназначен только для одноразового эмулятора, использует настоящее системное тестовое уведомление и проверяет фактический displayId окна, доставку NLS и удаление окна/модели после завершения сеанса.

### Итоговая повторная проверка

Итоговая сборка build19 прошла модульные тесты, сборку APK/test APK и lint без ошибок. На API 37 шторка дважды последовательно открылась одним реальным касанием после подтверждения видимого окна InputDispatcher; после завершения сеанса окно и модель удалены.

При проверке найдено системное ограничение обычных оверлеев: защищённый экран Android (в частности открытая страница беспроводной отладки) может устанавливать `HIDE_NON_SYSTEM_OVERLAY_WINDOWS` и скрывать такую шторку даже на дополнительном дисплее. После выхода из этой страницы на обычный главный экран шторка работает. Приложение сохраняет это ограничение Android и не подменяет окно системными флагами. Для повторяемой проверки используется обычный экран телефона, а для `cmd notification post` — ADB shell uid 2000: тестовый adbd root приписывает уведомление несуществующему пакету `root`.

Android 13 / API 33, build19: шторка также прошла проверку одного реального касания с доставленным NLS-уведомлением и очисткой после отключения. `PhoneCurtainProbe` подтвердил чёрное окно телефона, восстановление и независимое продолжение рисования на виртуальном экране. Чистый снимок: `../artifacts/0.6.0-local/qa-ui/notification-shade-api33.png`.

Полное первое сопряжение на API 33 пока не подтверждено: в подготовленном AVD системное действие параметров разработчика открывало `DevelopmentSettingsDisabledActivity`; при штатном включении режима разработчика отладочный транспорт эмулятора отключился. Это ограничение текущей проверки AVD. Реальная цепочка первого сопряжения и активации подтверждена на API 37 с обычным `adbd` uid 2000, без root; проверки шторки и затемнения на API 33 выполнены до этого и сохранены отдельно.

### Переход между способами доступа

Действующая активация HeadSwap владеет своей службой, даже когда сеанс CarLife остановлен. При выборе Shizuku или резервного ADB приложение сначала предлагает явное завершение активации и закрытие HeadSwap; выбранный новый способ и профиль до этого не записываются. Пользователь открывает приложение и повторяет выбор после завершения. Тот же gate применяется при смене профиля с другим сохранённым способом доступа, но не препятствует смене профиля с тем же backend.

Окончание `requestStop` не считается подтверждением освобождения ресурсов: lease сохраняет владельца до `end`, после shutdown нативного host. Автоматическое подключение не запускает другой backend в этот промежуток. Это использует существующее завершение доступа, не вводит параллельный host или перенос его нативного владения между процессами.

### Ручные параметры изображения

В выборе скорости появился пункт «Своя скорость…»: целое значение 1–20 Мбит/с. Оно сохраняется вместе с остальными параметрами, отображается в списке, а частота кадров остаётся динамической. Существующее «Своё разрешение» сохранено: чётные горизонтальные размеры 640–1920 × 480–1080; недопустимые значения не записываются. Кодировщик дополнительно проверяет фактическую комбинацию параметров при подключении. Значения по умолчанию 1280×720 и 128 DPI и прежние сохранённые параметры не меняются.
