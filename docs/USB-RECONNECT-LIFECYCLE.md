# Завершение старого сеанса при повторном USB-подключении

Это отдельное исправление жизненного цикла CarLife. Оно **не объясняет и не исправляет ANR DriveDeck**, показанный пользователем. Ошибка USB EIO также сама по себе не доказывает неисправность кабеля.

## Подтверждённая последовательность

В журнале версии 0.5.1 после EIO в 18:14:59 старый источник сохранялся на обычные восемь секунд. Новый запуск USB был запрошен в 18:15:07.226; старый источник подтвердил закрытие в .259. Новый сеанс уже открыл USB в .265 и начал протокол, однако в .284 был закрыт причиной «сервис уничтожен». Следующая попытка спустя двадцать секунд запустилась успешно.

Код 0.5.1 и прежний код 0.6.0 вызывали безусловный `stopSelf()` из `finish()`. Завершение старого источника могло попасть между принятием нового запроса Android и его доставкой в `onStartCommand`. Поэтому проверка только `session == null` не защищает новый запрос, который ещё находится в очереди Android.

## Изменения

- Сервис хранит последний доставленный `startId` и завершает собственную работу через `stopSelfResult(startId)`. Этот API проверяет также запросы запуска, которые Android уже принял, но ещё не доставил сервису. При отказе завершения сохраняются foreground, wake lock и ресурсы соединения. [Контракт Android Service](https://developer.android.com/reference/android/app/Service#stopSelfResult(int)).
- ACK предыдущего источника обрабатывает только свой текущий host. Он не изменяет восстановление или состояние нового владельца.
- Повторное соединение атомарно резервирует живой host и отменяет его grace до создания нового `CarLifeSession`. Раньше проверка `isDead` и отмена таймера были разделены, а отказ позднего `onUsbSessionStarted()` игнорировался.
- Каждый grace имеет отдельную идентичность: уже извлечённый из планировщика старый callback не может закрыть следующий grace после быстрого повторного отключения.
- Если срок уже истёк, создаётся новый host; запуск источника по-прежнему ждёт настоящего ACK закрытия предыдущего. Длительность grace остаётся **8000 мс**.

## Проверки

Добавлены детерминированные регрессии: новый запрос Android перед старым stop сохраняет foreground/wake lock; cleanup выполняется только после принятого stop; старый callback grace не закрывает зарезервированный host или следующий grace; истёкший host не переиспользуется, а замена ждёт ACK. Проверки не используют увеличение таймаута и не зависят от модели телефона.

Локальная сборка 0.6.0 build57 прошла: 1252 теста приложения (1225 успешных, 27 прежних пропусков AA), 7 тестов SDK, без ошибок. Все пять новых регрессий успешны; lint — 0 ошибок, 156 предупреждений. Основной APK: `641adc3630e4d9d2685cc366abd789ba246b02c57038209e808e29554f079f07`. Повтор физического USB-переподключения с этой сборкой ещё не выполнен.

Причина ANR DriveDeck остаётся неподтверждённой: системный отчёт зависания телефона коллеги недоступен. По просьбе пользователя дальнейший разбор этого случая отложен; обновление DriveDeck не считается доказанным исправлением ANR.
