# Как добавить профиль CarBridge на базе Android Desktop

Основа пилота — встроенный режим **Android Desktop** в HeadSwap. HeadSwap запускает свою оболочку и управляет родительским дисплеем ГУ. После установки и подтверждения подписанного адаптера пользователь может выбрать **«Профиль → CarBridge» на главном экране HeadSwap**, рядом с Android Desktop, DriveDeck и Samsung DeX. Эта запись запускает встроенный движок Android Desktop с интерфейсом автора. Целевой выпуск хоста — **HeadSwap Desktop 0.5.0**, версия контракта панели — **API v1**. Версия хоста 0.5.0-dev предназначена для тестирования. В локальном пилоте отдельно собирается адаптер UI CarBridge v0.43. Собственные примеры SDK HeadSwap используют другие ID. Подлинный самостоятельный CarBridge v0.43 не объявляет этот API; для использования проекта автора потребуется его отдельный адаптер. [Пример SDK](../examples/android-desktop-panel/README.md). Номер версии APK панели назначает её автор независимо от версий хоста и API. Текущая версия HeadSwap 0.4.1 позволяет проверить Activity как обычное приложение в окне Android Desktop.

Первый сценарий — **навигационное приложение и музыкальный виджет рядом**, с выбором стороны виджета. В самостоятельном CarBridge есть именно такой режим 70/30. Пока играет музыка, навигатор остаётся в живом окне и меняет ширину. [Описание режима в CarBridge v0.43](https://github.com/kukulkanod-source/CarBridge-Offline/blob/60fde51ccdce97047bafe96e3140293c6d4aa29d/README.md#L9-L27).

## Ответственность в пилоте

| Область | Команда HeadSwap | Автор CarBridge |
| --- | --- | --- |
| Сеанс и экран ГУ | Запускает штатную оболочку Android Desktop, владеет родительским дисплеем, USB/CarLife и кодером. | Поставляет и подписывает отдельный APK с панелью, которая работает в выделенной ей области оболочки. |
| Интерфейс | Показывает штатный интерфейс до выбора CarBridge. Кнопка возврата доступна во время работы панели. При её отсутствии, отзыве или сбое хост возвращает свой интерфейс в той же сессии. | Владеет сеткой, избранным и настройками панели. Сообщает выбор приложения, стороны виджета и желаемой компоновки. |
| Окна и медиа | Запускает приложения в сессионных окнах, управляет вводом, размером и DPI, проверяет разрешения на данные медиа. | Запрашивает разрешённую операцию через контракт и обрабатывает отказ. |
| Поставка | Публикует контракт и проверяет пакет, сертификат и совместимость. | Включает нужные UI-зависимости в свой APK и выпускает обновления под своим ключом. Базовая сборка HeadSwap остаётся самостоятельной. |

Профиль CarBridge использует только движок Android Desktop. Компонент устанавливается как отдельный APK. В списке профилей главного экрана пользователь выбирает **CarBridge** и подтверждает конкретного издателя. Выбор обычного Android Desktop возвращает штатный интерфейс. DriveDeck и Samsung DeX продолжают запускаться как самостоятельные профили.

## Последовательность для автора и сопровождающего HeadSwap

1. **Автор, сегодня.** Создать самостоятельный модуль или flavor с отдельным `applicationId` и своим ключом подписи. Выделить сетку и избранное в изменяемую по размеру Activity с фильтром `MAIN/LAUNCHER`. Проверить объединённый манифест APK. Для этой сборки достаточно обычной Activity. USB attach, захват экрана, ADB-сопряжение, scrcpy, системный overlay и управление питанием остаются вне неё. Самостоятельный CarBridge можно продолжать выпускать отдельно. [Пример обычного приложения](../examples/component-activity/README.md).
2. **Автор и пользователь, на 0.4.1.** Установить адаптер и открыть его из каталога Android Desktop. В этой версии Activity работает как приложение в дочернем окне. Проверить сетку, касания, Back и переподключение. Экран телефона должен сохранить свой масштаб. Оригинальный APK CarBridge, установленный как есть, открывает собственный основной экран.
3. **Сопровождающий и автор, к HeadSwap Desktop 0.5.0 / API v1.** Автор объявляет точку входа и версию по контракту. HeadSwap находит экспортированную Activity по контракту через Android PackageManager; централизованная регистрация пакета не требуется. Пользователь устанавливает APK, выбирает «Профиль → CarBridge» на главном экране и подтверждает предлагаемые пакет, Activity и SHA-256 сертификата. Название берётся из объявления Activity автора. Самостоятельная демо-панель примера появляется под своим собственным названием. При запуске режима хост сначала поднимает собственную оболочку, затем открывает панель только в выделенном для неё дочернем окне. Если компонент не установлен или завершился, хост показывает привычный экран Android Desktop. DriveDeck и Samsung DeX не участвуют в подключении панели. [Проект контракта](DESKTOP-COMPONENT-API.md).
4. **Компоновка.** Объявите `DASHBOARD` и `PROFILE_CHROME` на входной Activity. Она рисует своё домашнее окно, нижний док, избранное и музыкальную панель. Через `setDashboardLayout` автор задаёт сторону карточки, видимость окна приложения и высоту собственного дока. Хост размещает окно по этим параметрам. Профиль получает текущие данные плеера только с разрешения пользователя. Для закрытия своего меню верните приложению прежнюю рабочую область. [Контракт SDK](../sdk/desktop-panel-v1/README.md).
   Для иконок держите область нажатия и рисунок отдельно: широкая кнопка не должна растягивать значок. Локальный адаптер резервирует одну и ту же высоту для карты, музыки и дока; при 1280 × 720 и 128 DPI это 37 пикселей. Пересчитывайте размеры по дисплею Activity профиля при смене конфигурации. Для стартового восстановления карты дождитесь первого принятого `setDashboardLayout` и видимости Activity; ручной выбор пользователя отменяет ожидающее восстановление.
5. **Приёмка на ГУ.** Запустить Android Desktop без компонента и проверить штатный интерфейс. Выбрать CarBridge, начать тестовый маршрут, открыть виджет, сменить сторону и закрыть его. Убедиться, что задача навигатора осталась открытой и касания попадают в видимые элементы. Завершить панель и проверить возврат к штатному интерфейсу при работающей проекции. После переподключения USB старый идентификатор окна должен быть отклонён. Отдельно проверить отсутствие разрешения на медиа и удаление APK компонента.

## Что нужно согласовать с автором

Автор CarBridge прямо пишет, что лицензия для собственного кода пока не выбрана. Практичный путь — предложить **самому автору выпустить и сопровождать адаптер**. Для переноса чужих исходников или ресурсов в публичный репозиторий HeadSwap сначала нужно получить соответствующие права. Лицензии вложенных LibADB и scrcpy перечислены отдельно. Чистую сборку опубликованного снимка автор не подтверждает. [Заявление автора](https://github.com/kukulkanod-source/CarBridge-Offline/blob/60fde51ccdce97047bafe96e3140293c6d4aa29d/BUILDING.md#L26-L40) · [Пояснение GitHub о репозиториях без лицензии](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository).
