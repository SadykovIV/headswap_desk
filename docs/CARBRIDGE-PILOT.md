# Как автор CarBridge может встроить свой рабочий стол в HeadSwap

Первым пилотом стоит сделать **навигационное приложение и музыкальный виджет рядом**, с выбором стороны виджета. Так можно отдельно проверить ценность CarBridge для пользователя и работу будущего API. В самостоятельном CarBridge есть именно такой режим 70/30. Пока играет музыка, навигатор остаётся в живом окне и меняет ширину. [Описание режима в CarBridge v0.43](https://github.com/kukulkanod-source/CarBridge-Offline/blob/60fde51ccdce97047bafe96e3140293c6d4aa29d/README.md#L9-L27).

## Последовательность для автора и сопровождающего HeadSwap

1. **Автор, сегодня.** Создать самостоятельный модуль или flavor с новым `applicationId` и своим ключом подписи. Перенести в него сетку и избранное, сделать изменяемую по размеру Activity с фильтром `MAIN/LAUNCHER`. Проверить итоговый манифест именно этой сборки: ей достаточно обычной Activity, в ней не нужны обработчик USB attach, сервис захвата, беспроводное ADB-сопряжение, overlay или управление питанием телефона. Самостоятельный CarBridge остаётся отдельным продуктом. [Минимальный работающий пример](../examples/component-activity/README.md).
2. **Автор и пользователь, на 0.4.1.** Установить адаптер системным установщиком и открыть его из каталога Android Desktop. Проверить собственную сетку, касание, Back, поворот и переподключение. Критерий этапа — UI работает на внешнем дисплее, масштаб телефона сохраняется. APK оригинального CarBridge, установленный как есть, ведёт в его основной экран и не регистрирует новый профиль в HeadSwap.
3. **Сопровождающий, после реализации API v1.** Добавить поиск согласованной Activity и её выбор в «Компонентах». Привязать зарегистрированные пакет, класс и сертификат автора к текущему пользователю. Запустить Activity только на дисплее активной проекции. Дать пользователю кнопку возврата во встроенный Android Desktop при сбое провайдера. Автор добавляет отдельный фильтр и метаданные из спецификации. [Проект контракта](DESKTOP-COMPONENT-API.md).
4. **Обе стороны, на этапе компоновки.** Когда пользователь выбрал навигатор в сетке, обработчик `onLaunchApp` передаёт запрос на запуск разрешённой Activity хосту. При открытии музыки оболочка запрашивает компоновку «навигация 70%, медиа 30%, панель слева/справа». HeadSwap сохраняет окно навигатора и меняет только его геометрию. При закрытии музыки хост возвращает окну всю ширину. При отзыве доступа к медиа можно скрыть карточку и продолжить навигацию. Конкретный интерфейс для этого этапа пока не поставляется.
5. **Приёмка на ГУ.** Начать тестовый маршрут. Открыть виджет, сменить сторону, закрыть и проверить, что маршрут сохранился, окно не было запущено заново и касания попадают в те же видимые элементы. Переподключить USB, убедиться, что старый идентификатор окна отвергается, затем повторить тест с новой сессией. Отдельно проверить отсутствие медиа-разрешения, уход приложения в фон и аварийное завершение оболочки. Историю поездки и снимки карты для диагностики не требуется публиковать.

## Что нужно согласовать с автором

Автор CarBridge прямо пишет, что лицензия для собственного кода пока не выбрана. Практичный путь — предложить **самому автору выпустить и сопровождать адаптер**. Для переноса чужих исходников или ресурсов в публичный репозиторий HeadSwap сначала нужно получить соответствующие права. Лицензии вложенных LibADB и scrcpy перечислены отдельно. Чистую сборку опубликованного снимка автор не подтверждает. Этот план основан на анализе исходников и APK, аппаратная совместимость адаптера ещё не проверялась. [Заявление автора](https://github.com/kukulkanod-source/CarBridge-Offline/blob/60fde51ccdce97047bafe96e3140293c6d4aa29d/BUILDING.md#L26-L40) · [Пояснение GitHub о репозиториях без лицензии](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository).
