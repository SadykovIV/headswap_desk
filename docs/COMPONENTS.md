# Как подключить своё приложение к HeadSwap Desktop

В 0.4.1 есть один готовый путь для независимого автора. Выпустите обычное Android-приложение, подпишите своим ключом и откройте его из каталога Android Desktop. Пользователь увидит интерфейс на ГУ и сможет закрепить его на боковой панели. Этим способом можно поставить собственный плеер, экран диагностики или прототип новой оболочки.

Если приложение должно **заменить рабочий стол**, появиться в **«Компонентах HeadSwap Desktop»** или управлять расположением окон других программ, понадобится изменение хоста. Ниже разделены рабочий путь и проект такого изменения. [Стабильный выпуск 0.4.1](https://github.com/SadykovIV/headswap_desk/releases/tag/v0.4.1) · [Проект API компонентов](DESKTOP-COMPONENT-API.md) · [План адаптации CarBridge](CARBRIDGE-PILOT.md).

| Что хочет сделать автор | Что доступно |
| --- | --- |
| Показать собственную Activity на ГУ | Уже работает в Android Desktop 0.4.1. Установка через системный установщик. |
| Добавить приложение в коррекцию DPI | Уже работает. Пользователь добавляет пакет через «Исправить DPI приложения». Это настройка вывода, отдельно от установки. |
| Предложить свою оболочку вместо штатной | Проект API v1. Пользователь выбирает установленную оболочку, хост запускает её на внешнем дисплее. |
| Разместить чужой навигатор рядом со своим виджетом | Следующий этап. Хосту понадобится контракт компоновки и управления вложенными окнами. |

## Запустить первый экран в 0.4.1

1. **Возьмите минимальный пример** из ветки `main` или создайте Android-проект с одной Activity. В примере нет зависимостей от HeadSwap, фонового сервиса или разрешения USB. Пример добавлен после выпуска 0.4.1 и работает с его публичным APK. [Исходники и команды сборки](../examples/component-activity/README.md).
2. **Выберите собственный идентификатор и подпись.** Для распространяемого APK задайте свой стабильный `applicationId`, используйте постоянный ключ издателя и увеличивайте `versionCode` при обновлениях. Пакет автора устанавливается рядом с HeadSwap и DriveDeck. Для локальной проверки примера достаточно отладочной сборки. [Подпись Android-приложений](https://developer.android.com/studio/publish/app-signing).
3. **Сделайте точку входа видимой.** Экспортируйте одну включённую Activity с `android.intent.action.MAIN` и `android.intent.category.LAUNCHER`, разрешите изменение размера через `android:resizeableActivity="true"`. На этом входе не запрашивайте закрытое разрешение. HeadSwap обнаруживает запускаемые Activity и повторно проверяет экспорт, разрешение и принадлежность точки входа пакету перед запуском. [Обнаружение приложений в 0.4.1](https://github.com/SadykovIV/headswap_desk/blob/v0.4.1/android/app/src/main/java/com/headswap/desk/desktop/AndroidDesktopActivity.kt#L254-L274) · [Проверка точки входа](https://github.com/SadykovIV/headswap_desk/blob/v0.4.1/android/app/src/main/java/com/headswap/desk/desktop/DesktopAppPane.kt#L130-L155).
4. **Установите приложение и проверьте его через ГУ.** На телефоне с Android 13 или новее установите HeadSwap 0.4.1 и свой APK. Выберите профиль Android Desktop, активируйте доступ обычным способом и подключитесь к ГУ или USB-эмулятору CarLife. Откройте каталог на ГУ, затем своё приложение. В примере выводятся номер дисплея и плотность окна. При запуске через ГУ номер должен быть положительным. Нажмите кнопку примера, нажмите «Назад», откройте его снова через каталог. [Установка и активация HeadSwap](../INSTALL.md).
5. **Проверьте жизненный цикл.** Во время проекции переключитесь в другое приложение и вернитесь. Переподключите USB. Приложение должно восстановить собственное состояние. Номера дисплеев между сеансами могут измениться. Если изменили разрешение или DPI в HeadSwap, начните новую сессию и сравните данные окна. Размер интерфейса считывайте через контекст Activity на ГУ. Исходный системный DPI телефона должен сохраняться. [Android и несколько дисплеев](https://developer.android.com/develop/ui/compose/layouts/adaptive/support-connected-displays).

Для диагностики с рабочей станции можно отдельно проверить, зарегистрирована ли точка входа. Подставьте серийный номер своего тестового устройства и имя своего пакета. Ниже указано имя пакета примера.

```sh
adb -s "$SERIAL" shell cmd package resolve-activity --brief \
  -a android.intent.action.MAIN -c android.intent.category.LAUNCHER com.example.headswap.displayinfo
```

Команда должна вернуть нужный компонент примера `com.example.headswap.displayinfo/.DisplayInfoActivity`. Фактический запуск проверяется нажатием в каталоге HeadSwap. Запуск через `adb shell am start` проверил бы действие пользователя shell с другими полномочиями. Если значок отсутствует, проверьте установленный пакет в текущем Android-пользователе, фильтр Activity и её состояние. Если виден интерфейс телефона, проверьте, откуда запущена Activity, и не переиспользуется ли отдельная телефонная задача с `singleTask`. [Правила запуска задач на дисплеях](https://source.android.com/docs/core/display/multi_display/activity-launch).

## Как устроены «Компоненты» сейчас

Основной HeadSwap и адаптированный DriveDeck имеют отдельные маршруты обновления. Список дополнительных компонентов в 0.4.1 задан в коде. Установщик из файла проверяет известный пакет, код версии и подпись до передачи APK системному установщику. Экран не импортирует сторонний лаунчер как новый профиль. Сам внешний сервис DriveDeck дополнительно проверяет вызывающий UID, разрешение уровня `signature` и подпись приложения. Независимому издателю ключ HeadSwap для разработки собственного приложения не нужен. [Каталог текущей версии](https://github.com/SadykovIV/headswap_desk/blob/v0.4.1/android/app/src/main/java/com/headswap/desk/update/ComponentCatalog.kt) · [Проверка пакета](https://github.com/SadykovIV/headswap_desk/blob/v0.4.1/android/app/src/main/java/com/headswap/desk/update/ComponentPackages.kt) · [Граница доступа DriveDeck](https://github.com/SadykovIV/headswap_desk/blob/v0.4.1/android/app/src/main/java/com/headswap/desk/embed/EmbeddedDisplayService.kt#L12-L35).

## Что передать сопровождающим для первого профиля

Для обсуждения пилота подготовьте пакет и класс входной Activity, ссылку на публичный тестовый выпуск, SHA-256 APK, отпечаток SHA-256 **публичного** сертификата издателя, минимальную версию Android и перечень необходимых возможностей. Отдельно приложите результаты прогона на ГУ: где открылось окно, как отработали Back и переподключение, какой DPI получил экран. Закрытый ключ остаётся у издателя. По результатам такого пилота можно согласовать версию контракта, включение профиля в каталог и порядок обновления. [Порядок допуска и план реализации](DESKTOP-COMPONENT-API.md).
