# Как подключить своё приложение к HeadSwap Desktop

Чтобы показать отдельное окно на ГУ, выпустите обычное Android-приложение, подпишите своим ключом и откройте его из каталога Android Desktop. Пользователь увидит интерфейс на ГУ и сможет закрепить его на боковой панели. Этим способом можно поставить собственный плеер, экран диагностики или прототип панели для Android Desktop.

**Платформа компонентов принадлежит HeadSwap.** В HeadSwap Desktop 0.5.1 независимый разработчик может объявить свою Activity как профиль. Пользователь открывает на главном экране «Профиль» и видит собственные режимы HeadSwap, CarBridge и другие установленные панели. Хост сохраняет родительский экран, кнопки и ввод, а лаунчер может реализовывать собственную сетку, избранное, панели и просить хост открыть выбранную программу. CarBridge использует только наш движок Android Desktop. Профили DriveDeck и Samsung DeX сохраняют свои пути запуска. [SDK v1 и пошаговая интеграция](../sdk/desktop-panel-v1/README.md) · [Скачать SDK v1](https://github.com/SadykovIV/headswap_desk/releases/download/v0.5.1/HeadSwap-Profile-SDK-v1-dev.zip) · [План CarBridge](CARBRIDGE-PILOT.md).

| Что хочет сделать автор | Что доступно |
| --- | --- |
| Показать собственную Activity на ГУ | Поддерживается в Android Desktop начиная с 0.4.1. Установка через системный установщик. |
| Добавить приложение в коррекцию DPI | Уже работает. Пользователь добавляет пакет через «Исправить DPI приложения». Это настройка вывода, отдельно от установки. |
| Выпустить собственный профиль с лаунчером | SDK v1. Профиль выбирается на главном экране. Хост проверяет пакет и сертификат и открывает панель внутри собственного рабочего стола. |
| Из своего лаунчера открыть установленное приложение или штатный каталог | В SDK v1 есть запросы `requestLaunch` и `openCatalog`. У них проверяется вызывающий UID и текущее окно. |
| Разместить чужой навигатор рядом со своим виджетом | Следующий этап. Хосту понадобится контракт компоновки и управления вложенными окнами. |

## Кто владеет интерфейсом и сессией

| Часть системы | Владелец и ответственность |
| --- | --- |
| Ядро HeadSwap | Согласование CarLife, создание и завершение сеанса, кодер, размеры и плотность виртуальных дисплеев, звук, касания, клавиатура и подписки приборки. |
| Хост Android Desktop в HeadSwap | Родительская Activity, системные кнопки «Домой» и «Назад», каталог, проверка издателя и запуск компонентов. При удалении или падении панели показывает встроенный каталог в том же сеансе. |
| Профиль CarBridge | Независимый APK автора. Через API v1 лаунчер запрашивает открытие допустимой Activity. Свои элементы он может разложить 70/30 уже сейчас. Для компоновки живого навигатора и музыкальной карточки хоста понадобится следующий этап. |
| Профили DriveDeck и Samsung DeX | Их выбор, запуск и разрешения остаются самостоятельными. Компонент Android Desktop для них не активируется. |

## Запустить первый экран в Android Desktop

1. **Возьмите минимальный пример** из ветки `main` или создайте Android-проект с одной Activity. В примере нет зависимостей от HeadSwap, фонового сервиса или разрешения USB. Пример добавлен после выпуска 0.4.1 и работает с его публичным APK. [Исходники и команды сборки](../examples/component-activity/README.md).
2. **Выберите собственный идентификатор и подпись.** Для распространяемого APK задайте свой стабильный `applicationId`, используйте постоянный ключ издателя и увеличивайте `versionCode` при обновлениях. Пакет автора устанавливается рядом с HeadSwap и DriveDeck. Для локальной проверки примера достаточно отладочной сборки. [Подпись Android-приложений](https://developer.android.com/studio/publish/app-signing).
3. **Сделайте точку входа видимой.** Экспортируйте одну включённую Activity с `android.intent.action.MAIN` и `android.intent.category.LAUNCHER`, разрешите изменение размера через `android:resizeableActivity="true"`. На этом входе не запрашивайте закрытое разрешение. HeadSwap обнаруживает запускаемые Activity и повторно проверяет экспорт, разрешение и принадлежность точки входа пакету перед запуском. [Обнаружение приложений в 0.4.1](https://github.com/SadykovIV/headswap_desk/blob/v0.4.1/android/app/src/main/java/com/headswap/desk/desktop/AndroidDesktopActivity.kt#L254-L274) · [Проверка точки входа](https://github.com/SadykovIV/headswap_desk/blob/v0.4.1/android/app/src/main/java/com/headswap/desk/desktop/DesktopAppPane.kt#L130-L155).
4. **Установите приложение и проверьте его через ГУ.** На телефоне с Android 13 или новее установите HeadSwap Desktop 0.5.1 и свой APK. Выберите профиль Android Desktop, активируйте доступ обычным способом и подключитесь к ГУ или USB-эмулятору CarLife. Откройте каталог на ГУ, затем своё приложение. В примере выводятся номер дисплея и плотность окна. При запуске через ГУ номер должен быть положительным. Нажмите кнопку примера, нажмите «Назад», откройте его снова через каталог. [Установка и активация HeadSwap](../INSTALL.md).
5. **Проверьте жизненный цикл.** Во время проекции переключитесь в другое приложение и вернитесь. Переподключите USB. Приложение должно восстановить собственное состояние. Номера дисплеев между сеансами могут измениться. Если изменили разрешение или DPI в HeadSwap, начните новую сессию и сравните данные окна. Размер интерфейса считывайте через контекст Activity на ГУ. Исходный системный DPI телефона должен сохраняться. [Android и несколько дисплеев](https://developer.android.com/develop/ui/compose/layouts/adaptive/support-connected-displays).

Для диагностики с рабочей станции можно отдельно проверить, зарегистрирована ли точка входа. Подставьте серийный номер своего тестового устройства и имя своего пакета. Ниже указано имя пакета примера.

```sh
adb -s "$SERIAL" shell cmd package resolve-activity --brief \
  -a android.intent.action.MAIN -c android.intent.category.LAUNCHER com.example.headswap.displayinfo
```

Команда должна вернуть нужный компонент примера `com.example.headswap.displayinfo/.DisplayInfoActivity`. Фактический запуск проверяется нажатием в каталоге HeadSwap. Запуск через `adb shell am start` проверил бы действие пользователя shell с другими полномочиями. Если значок отсутствует, проверьте установленный пакет в текущем Android-пользователе, фильтр Activity и её состояние. Если виден интерфейс телефона, проверьте, откуда запущена Activity, и не переиспользуется ли отдельная телефонная задача с `singleTask`. [Правила запуска задач на дисплеях](https://source.android.com/docs/core/display/multi_display/activity-launch).

## Обновления и удаление компонентов

В **Настройки → Компоненты HeadSwap Desktop** у основного приложения, DriveDeck и каждого установленного профиля есть карточка с названием и версией. Для независимого профиля можно выбрать «Обновить из APK…» или «Удалить компонент…». Для обновления APK автор использует тот же пакет и ключ подписи. Сертификат HeadSwap нужен для совместимого DriveDeck, а собственные профили издатели подписывают своими ключами. [Установка и обновление собственного профиля](../sdk/desktop-panel-v1/DEVELOPER-GUIDE.md).

## Что передать сопровождающим для первого компонента Android Desktop

Для обсуждения пилота подготовьте пакет и класс входной Activity, ссылку на публичный тестовый выпуск, SHA-256 APK, отпечаток SHA-256 **публичного** сертификата издателя, минимальную версию Android и перечень необходимых возможностей. Отдельно приложите результаты прогона на ГУ: где открылось окно, как отработали Back и переподключение, какой DPI получил экран. Закрытый ключ остаётся у издателя. Для локального подключения достаточно установить подписанный APK и выбрать профиль на главном экране. Для будущей централизованной доставки потребуется отдельная процедура допуска. [Порядок допуска и план реализации](DESKTOP-COMPONENT-API.md).
