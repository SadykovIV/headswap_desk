# Повторная проверка HeadSwap Desktop 0.6.0

Дата: 9 ноября 2026 года. Проверяется локальная версия 0.6.0, code43. Публикация на GitHub отложена до ручной проверки. Этот отчёт уточняет первоначальный план: наличие кода и успешный тест отдельного механизма не означают, что все требования выполнены на каждой магнитоле.

## Что исправлено именно повторной проверкой

- Уведомления: уникальная идентичность каждого ответа/отмены и явная обработка заблокированного канала. Старое действие не должно запускать новую активацию или портить текущую.
- Беспроводной режим: общий порядок подготовки доступа, отмена всех ресурсов ожидания при выключении, восстановление рабочего стола при живом TCP6, разрешение штатных callback компонентов и управления панелью.
- TCP6: отдельный 15-секундный срок сборки каналов после первого сокета. Неудачная неполная попытка освобождает соединения и адрес; общий срок поиска магнитолы сохраняется.
- Аппаратный ввод: семантический фокус собственного каталога вместо движения только по строкам; сброс старого Back на других действиях. Собственный диалог временно получает фокус родителя и возвращает его дочернему приложению после закрытия. Обычный Back для host проходит через проверяемый callback вместо инъекции в нефокусируемое родительское окно. Перед выполнением проверяются поколение сеанса, регистрация Activity, диалог и текущий запрос дочернего окна; старая команда не переадресуется новому приложению. Private protocol обновлён до 17, публичный SDK компонентов сохранён.
- Видео: исходное монотонное время native Surface проходит через GL и ограничитель FPS в MediaCodec. Повтор статичного кадра не создаёт постоянного сдвига времени последующих кадров.
- Формат времени проверен независимо от оригинального HeadSwap по локальному APK Baidu CarLife 8.8.2 с проверенной подписью: `Recorder.sendVideoData` записывает секунды в VIDEO, а `MusicAudioHelper` через `PCMPackageHead` — миллисекунды в PCM. В коде используются отдельные преобразования этих полей. Это свидетельство реализации Baidu, а не найденная публичная нормативная спецификация для любой версии ГУ. Архивные приёмники Baidu не используют эту метку для точного воспроизведения, поэтому совпадение полей не доказывает синхронизацию на Honda.
- Частота: низкий запрос native-ГУ действительно снижает верхнюю частоту, включая совместимый режим Mobis.

## Рефакторинг и оптимизация

Проведён рефакторинг затронутых границ: политика соединения и отмены, готовность конкретного ADB endpoint, управление вводом, независимость дисплея, ограничение FPS, часы PCM/Surface, ограничения очередей, модель уведомлений, обложки и проверяемые адаптеры компонентов. Эти правила отделены от Android-сервисов и имеют собственные регрессионные проверки. Удалены найденные USB-only условия из общих путей и объединена очистка беспроводного запуска.

**Полный рефакторинг всего репозитория не завершён.** `AaBridge`, `CarLifeSession`, `BridgeService`, `DexSetupActivity` и `SettingsScreen` всё ещё крупные классы. Механическое перемещение их строк не считается улучшением. Также сохранено прежнее исключение для гашения панели HONOR ABR-LX1: убрать известную защиту без повторной проверки устройства означало бы риск регрессии. Это частный случай, и он не выдаётся за универсальную архитектуру.

Следующая архитектурная работа — дальнейшее разделение владельцев транспорта/медиа/интерфейса с сохранением контрактных проверок. Числа производительности всей системы на физических ГУ пока не получены; «оптимизировано всё возможное» не заявляется.
